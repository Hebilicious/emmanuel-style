# emmanuel.style

The Astro app behind [emmanuel.style](https://emmanuel.style): a terminal-flavoured
newspaper. Monospace chrome, ruled panels, one column of text, and exactly two themes.

## Stack

| Concern    | Choice                                                          |
| ---------- | --------------------------------------------------------------- |
| Framework  | Astro 7, static output                                          |
| Islands    | Vue 3 through `@astrojs/vue`                                    |
| Styling    | [cssforge](https://github.com/Hebilicious/cssforge) tokens only |
| Headings   | [Nabla](https://fonts.google.com/specimen/Nabla), self-hosted   |
| Body       | Monaspace Argon, self-hosted                                    |
| Navigation | Astro `ClientRouter` (SPA page swaps)                           |
| Offline    | Workbox service worker generated at build time                  |
| Backend    | `packages/api`, Workers with Durable Objects                    |
| Deployment | Cloudflare Workers assets through `wrangler deploy`             |

## Commands

```sh
pnpm install
pnpm dev      # regenerate tokens, then serve with HMR
pnpm build    # regenerate tokens, then build to dist/
pnpm preview  # serve the built site
pnpm check    # astro check (types and content)
pnpm deploy   # wrangler deploy
```

The favourites and star features need `packages/api` running. Its README covers
that, including the dev proxy and the `PUBLIC_API_BASE` build variable.

## Design tokens

`cssforge.config.ts` is the single source of truth for colour, spacing and type. It
generates `src/styles/cssforge.css`, which is committed so the CSS is reviewable, and
`pnpm dev` / `pnpm build` regenerate it first.

The palette comes from five coolors anchors
(`coolors.co/75f4f4-90e0f3-b8b3e9-d999b9-d17b88`). Those anchors are all high
lightness, so `scripts/derive-palette.mjs` expands each one into a full ramp by
walking OKLCH lightness and chroma while holding the anchor's hue, clamping every
step into sRGB. That script also asserts the WCAG contrast of every
foreground/background pairing both themes use, and exits non-zero if one fails.

```sh
node scripts/derive-palette.mjs   # print ramps and run the contrast gates
```

Two themes exist, `LightTheme` and `DarkTheme`. Each exposes the same variable
names, so a component never branches on the theme:

| Variable        | Role                                  |
| --------------- | ------------------------------------- |
| `--paper`       | page background                       |
| `--ink`         | body text                             |
| `--rule`        | hairline rules                        |
| `--rule-strong` | heavy and double rules, panel borders |
| `--surface`     | boxed panels                          |
| `--sunk`        | inset fills, chart bars               |
| `--muted`       | secondary text                        |
| `--faint`       | meta text, uppercase labels           |
| `--accent`      | section marks, active states          |
| `--secondary`   | cool counterpoint                     |
| `--tertiary`    | graph series and highlights           |
| `--link`        | links inside article copy             |

Spacing and type are fluid, generated by cssforge from viewport-interpolated
clamps. Components never write a raw length:

| Token family                             | Use                                     |
| ---------------------------------------- | --------------------------------------- |
| `--typography_fluid-display-font-size-*` | mastheads and page titles               |
| `--typography_fluid-content-font-size-*` | body copy and article headings          |
| `--typography_fluid-micro-font-size-*`   | meta lines, labels, footers             |
| `--spacing_fluid-flow-space-*`           | vertical rhythm between blocks          |
| `--spacing_fluid-tight-space-tight-*`    | rhythm inside a block                   |
| `--spacing_fluid-gutter-space-gutter-*`  | page gutters                            |
| `--spacing-size-*`                       | the few fixed values (hairlines, rules) |

## Navigation

`ClientRouter` from `astro:transitions` swaps the page instead of reloading the
document, so moving between sections keeps scroll state and page state. Scripts
that must react to a swap listen for `astro:page-load`, because a `<script>` tag
in a page body runs on the first load and again after every swap.

## Offline

The `offline-support` integration in `astro.config.ts` runs after Astro finishes
writing `dist/`. It writes `manifest.webmanifest`, bundles `src/service-worker.ts`
with esbuild, then calls `workbox-build`'s `injectManifest` to inject the precache
manifest into that bundle. Every emitted page, script, stylesheet, font and image
is precached into `sw.js`.

`injectManifest` is used rather than `generateSW` because navigation needs custom
handling. Pages are built as directories (`/experience/index.html`) and the site's
links are written without a trailing slash, while Workbox's precache route only
resolves the trailing-slash spelling. The worker therefore answers navigations
from its own `fetch` listener, trying `/experience/index.html` and
`/experience.html` before going to the network.

Both fonts are copied into the build, so the site never requests a third party at
runtime. `/api/*` is deliberately outside the precache: counts are live data, so
the client asks for them when online and renders without them when offline.
Verified by loading the site, cutting the network, and navigating to every route
in both spellings (`/experience` and `/experience/`): pages, fonts, islands and
the experience chart all render, star counts stay blank rather than wrong, and
the favourite control stays present and clickable.
